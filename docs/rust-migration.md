# Rust: запуск, проверка и выпуск

Rust обслуживает обе версии домена WIRING, API сайта и приложений, админку и фоновые задачи. Клиенты используют прежние URL, форматы сессий и PostgreSQL. Прошлый backend отключён на продакшене с 15 ноября 2026 года; его исходники и тестовый клиент удалены из рабочей ветки. История Git сохраняет прежние этапы переноса.

Локальный запуск: `./scripts/dev.sh`. nginx доступен на `127.0.0.1:5070`; Rust и PostgreSQL остаются внутри сети Docker. `./scripts/test-api.sh` поднимает отдельный проект и проверяет публичный HTTP-контракт, включая cookie и Bearer, регистрацию, загрузку файлов, поддержку и правила хранения сообщений. В тестах нет продакшен-аккаунтов и вызовов провайдеров.

## Публикация и откат

GitHub Actions собирает Linux-бинарник, каталог, документы и клиент после проверок. Задача деплоя выкладывает тот же артефакт. Ручная сборка использует `deploy/build-rust-release.sh`.

Скрипт `deploy.sh` переключает `/opt/wiring-places/current`, публикует статические файлы и перезапускает Rust. До и после переключения он проверяет каталоги обоих доменов через TLS и убеждается, что nginx не направляет трафик на Flask. На сервере, где прежний сервис ещё установлен, он должен быть остановлен и отключён; порт 5070 в любом случае не должен слушать. При ошибке проверки скрипт возвращает предыдущий Rust-релиз и прежний клиент. nginx и systemd настраиваются отдельно. Рабочую PostgreSQL и каталог пользовательских загрузок деплой не заменяет.

Модерация фото, расшифровка по запросу, ответы админки и синхронизация согласившихся контактов используют текущие рабочие интеграции. Резервное копирование PostgreSQL остаётся системной задачей.
